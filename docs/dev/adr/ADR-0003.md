# ADR-0003: Adaptive Basis Set Escalation

**Date:** 2025-04-22
**Status:** Proposed

## Context

SAPT calculations exhibit strong basis set dependence. Running with a very large basis set (e.g., aug-cc-pVTZ or larger) is computationally expensive, but necessary for high accuracy. However, for many applications or intermediate geometries, a smaller basis set might provide sufficient accuracy, saving significant computational cost. We need a mechanism to automatically select an appropriate basis set based on user-defined accuracy requirements.

## Decision

We will implement an adaptive basis set escalation workflow (`AdaptiveWorkflow`) that performs SAPT calculations iteratively up a predefined basis set ladder. The workflow will stop when the change in key SAPT components between successive rungs falls below user-specified tolerances, or when the highest rung in the ladder is reached.

-   **Basis Ladder:** The default ladder will be `["jun-cc-pVDZ", "aug-cc-pVDZ", "jun-cc-pVTZ", "aug-cc-pVTZ"]`. This will be stored as a constant `BASIS_LADDER` in `saptase.core.basis`.
-   **Tolerances:** Users will specify absolute energy difference tolerances (in kcal/mol) for individual SAPT components (e.g., `elst`, `exch`, `ind`, `disp`) and/or the total SAPT energy (`sapt_total`) in the job configuration file.
-   **Comparison:** After each rung `i > 0`, the workflow compares `abs(E_component[i] - E_component[i-1])` against the corresponding tolerance.
-   **Stopping Criteria:** The workflow stops if *all* specified component differences are below their respective tolerances, or if the `max_rung` specified by the user (or the end of the ladder) is reached.
-   **Result:** The final `SaptResult` will indicate the basis set used for the converged calculation and include the energy components from that level. Intermediate results might be stored for analysis but aren't the primary output.

## Alternatives Considered

-   **Fixed Basis:** Simplest approach, but inefficient as it doesn't adapt to accuracy needs.
-   **Extrapolation Schemes:** Techniques like Complete Basis Set (CBS) extrapolation exist but add complexity beyond the scope of this initial adaptive implementation. They could be considered later.
-   **More Complex Ladders:** Could define different ladders or allow fully custom ladders, but starting with a fixed, common ladder simplifies initial implementation.

## Consequences

-   Requires modifications to the workflow orchestration to handle iterative calculations and result comparisons.
-   Introduces new configuration options for tolerances and max rung.
-   `SaptTask` might need to evolve to clearly associate results with specific basis sets if intermediate results are stored explicitly. (Initially, we can focus on just propagating the final converged result).
-   Testing requires mock backends that simulate basis set convergence behaviour.
