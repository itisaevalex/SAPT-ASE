# SAPT(DFT) Automation: Tools, Workflows, and Current Developments

## SAPT Implementations and Automation Workflows

**Open-Source SAPT Codes:** The primary open-source platform for SAPT calculations is **Psi4**, which implements SAPT at various levels (SAPT0, higher-order SAPT, and SAPT based on DFT monomer descriptions)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=both%20closed,index%20electron%20repulsion)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=SAPT). Psi4 can directly compute the intermolecular interaction energy without needing separate monomer and dimer energy calculations, and provides the energy **decomposed into physically meaningful components** (electrostatics, exchange, induction, dispersion)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=Symmetry,each%20monomer%20and%20the%20interaction)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=interaction%20energy%20is%20determined%20without,each%20monomer%20and%20the%20interaction). Psi4’s SAPT module supports closed-shell dimers (singlet monomers) and uses modern **density-fitting** techniques to accelerate four-index integrals​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=both%20closed,index%20electron%20repulsion)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=singlets,index%20electron%20repulsion). Notably, Psi4 includes an implementation of **SAPT(DFT)** – SAPT using Kohn-Sham monomers – which generally improves accuracy over SAPT0 (HF-based) at the cost of higher computation​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=In%20general%2C%20SAPT,memory%20to%20hold%20%20doubles)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=SAPT,memory%20to%20hold%20%20doubles). SAPT(DFT) in Psi4 was successfully applied to systems with up to ~2000 basis functions (scalable to ~3000)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=components%2C%20and%20overall%20interaction%20energies%2C,memory%20to%20hold%20%20doubles)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=still%20be%20applied%20to%20medium,memory%20to%20hold%20%20doubles). Besides Psi4, the most comprehensive SAPT codebase is the **SAPT2020** suite (from the Szalewicz group), which encompasses _virtually all SAPT variants_ (perturbative HF-based, DFT-based, coupled-cluster SAPT, open-shell SAPT, even three-body SAPT)​[pubmed.ncbi.nlm.nih.gov](https://pubmed.ncbi.nlm.nih.gov/32414261/#:~:text=Symmetry,surfaces%20since%20it%20is%20seamlessly)​[pubmed.ncbi.nlm.nih.gov](https://pubmed.ncbi.nlm.nih.gov/32414261/#:~:text=perturbative%2C%20coupled%20cluster%2C%20and%20density,degrees%20of%20freedom%20of%20monomers). SAPT2020 is designed for generating entire potential energy surfaces of intermolecular interactions automatically​[pubmed.ncbi.nlm.nih.gov](https://pubmed.ncbi.nlm.nih.gov/32414261/#:~:text=monomers,degrees%20of%20freedom%20of%20monomers)​[pubmed.ncbi.nlm.nih.gov](https://pubmed.ncbi.nlm.nih.gov/32414261/#:~:text=is%20the%20preferred%20approach%20for,degrees%20of%20freedom%20of%20monomers), and can interface with external quantum codes (e.g. using ORCA or DALTON for monomer DFT calculations)​[pubs.aip.org](https://pubs.aip.org/aip/jcp/article-pdf/doi/10.1063/5.0005093/16684611/184109_1_online.pdf#:~:text=SAPT%20codes%20for%20calculations%20of,ORCA)​[pubs.aip.org](https://pubs.aip.org/aip/jcp/article-pdf/doi/10.1063/5.0005093/16684611/184109_1_online.pdf#:~:text=186%20These%20codes%20can%20be,ORCA). However, SAPT2020 is an academic code (Fortran-based) and not as directly integrable into Python workflows as Psi4. On the commercial side, Q-Chem offers an “**XSAPT**” approach (extended SAPT) that combines SAPT0 with explicit polarization (XPol) and dispersion corrections​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=Most%20calculations%20reported%20here%20are,version%2C56%20which%20we%20do%20not)​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=reported%20using%20XSAPT%20%2B%20aiD3%2C48%2C58,57%2C58), and programs like Molpro have legacy SAPT implementations​[molpro.net](https://www.molpro.net/manual/doku.php?id=symmetry-adapted_intermolecular_perturbation_theory#:~:text=cb%3D2102)​[github.com](https://github.com/psi4/psi4/issues/939#:~:text=It%20would%20be%20a%20good,moment%20as%20the%20GRAC), but these are less accessible for automation due to licensing and lack of Python APIs.

**Psi4 Plugin Architecture and Python API:** One strength of Psi4 for automation is its design as a **Python-driven library**. Users can import Psi4 in Python and call its functions (the PsiAPI) to programmatically set up molecules, basis sets, and execute `psi4.energy("sapt0")` or `psi4.energy("sapt(dft)")` to obtain SAPT results​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=A%20complete%2C%20minimal%20example%20of,DFT%29%20computation%20is%20given%20below)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=energy). This makes it straightforward to integrate into custom workflows. For example, one can loop over many dimer geometries in Python and compute SAPT components for each, catching errors and adjusting settings as needed (see **Error Handling** below). Psi4 also supports a plugin system for extending its functionality​[psicode.org](https://psicode.org/psi4manual/master/prog_ways_to_add.html#:~:text=Ways%20to%20Add%20Code%3A%20Psi4NumPy%2C,prototyping%20new%20methods%20in%20Psi4). In practice, new methods can be prototyped using the Psi4NumPy framework (writing Python code that uses Psi4’s integrals and wavefunctions)​[psicode.org](https://psicode.org/psi4manual/master/prog_ways_to_add.html#:~:text=Ways%20to%20Add%20Code%3A%20Psi4NumPy%2C,prototyping%20new%20methods%20in%20Psi4)​[psicode.org](https://psicode.org/psi4manual/master/prog_ways_to_add.html#:~:text=developing%20and%20prototyping%20new%20methods,in%20Psi4), or compiled as plugins in C++ for performance​[psicode.org](https://psicode.org/psi4manual/4.0b3/plugins#:~:text=Plugins%3A%20Adding%20New%20Functionality%20to,plugin%2C%20run%20the%20following). This modularity has enabled community plugins like **OpenFermion-Psi4** (for quantum computing integration)​[github.com](https://github.com/quantumlib/OpenFermion-Psi4#:~:text=quantumlib%2FOpenFermion,to%20interface%20with%20OpenFermion). While no specific third-party “SAPT plugin” is needed (SAPT is built-in), this architecture means one could, for instance, write a plugin to automate multi-step SAPT workflows or interface with external tools.

**Integration with ASE (Atomic Simulation Environment):** ASE provides a unified way to handle molecular geometries and calculations. A basic Psi4 **ASE Calculator** exists​[github.com](https://github.com/medford-group/ase-psi4#:~:text=Image%3A%20Build%20Status)​[github.com](https://github.com/medford-group/ase-psi4#:~:text=A%20simple%20ase%20calculator%20for,calc.psi4) that allows single-point energy and gradient computations by Psi4 through ASE. For example, one can attach `ase_psi4.Psi4` as a calculator to an ASE `Atoms` object and call `atoms.get_potential_energy()` to obtain (for instance) a DFT or CCSD(T) energy​[github.com](https://github.com/medford-group/ase-psi4#:~:text=from%20ase_psi4,molecule%20import%20numpy%20as%20np)​[github.com](https://github.com/medford-group/ase-psi4#:~:text=atoms). However, **SAPT calculations require special handling of fragments**, which the default ASE Psi4 interface does not directly expose. In Psi4, a dimer must be defined as two fragments (monomer A and B). The ASE Psi4 calculator currently treats the entire Atoms object as one molecule, so to do SAPT one must modify the input or call Psi4 manually. A simple approach is to bypass the ASE calculator for SAPT: use ASE to generate or manipulate geometries, then use Psi4’s Python API to define the molecule with fragments and run SAPT. For instance, one can build an ASE `Atoms` for a dimer, then in Python do:

geom = "\n--\n".join([ase_atoms_to_xyz(mol) for mol in (monA, monB)])
psi4.geometry(geom)
psi4.energy('sapt(dft)')

**where `--` in the geometry separates fragments for Psi4. This ensures the **standard Psi4 partitioning** of the dimer into two monomers​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=The%20SAPT%20module%20uses%20the,of%20the%20system%20to). In fact, Psi4 will throw an error if one attempts a three-fragment input (since three-body SAPT is unsupported)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=SAPT%3A%20Symmetry,is%20not%20currently%20supported), enforcing exactly two fragments for SAPT. Thus, integration with ASE is achievable but may require a custom workflow. One pattern is to use ASE to sample configurations (for example, pulling a water dimer apart, generating many geometries), and for each, call Psi4’s SAPT via a Python loop. **Error handling** can be added around the Psi4 call (e.g., in a try/except block) to catch SCF failures or memory issues and adjust settings on the fly (discussed below). In summary, Psi4’s Python interface and plugin capability make it well-suited for building a **robust SAPT(DFT) automation module**. ASE can be used for structure management, while Psi4 handles the quantum calculations. This combination leverages ASE’s geometry engines (e.g., building dimers, scanning coordinates) with Psi4’s deep SAPT functionality. Recent efforts by users confirm this approach: e.g., using ASE’s Psi4 calculator as a template but manually specifying fragment divisions​[gitlab.com](https://gitlab.com/ase/ase/-/issues/1102#:~:text=How%20to%20set%20a%20calculator,divide%20your%20atoms%20into). In practice, one might maintain a library of **workflow functions** – for example, a function that given two molecules (ASE Atoms) and a separation, automatically sets up Psi4, tries a SAPT calculation, and returns components or retries with altered settings if an error occurs. This kind of high-level automation is exactly what Psi4’s design enables.

## Basis Set Convergence for SAPT(DFT) in Hydrogen-Bonded Systems

**Diffuse Functions and Accuracy:** SAPT interaction energies, especially for **hydrogen-bonded dimers** (like water dimer, ammonia dimer) and general benchmark sets (S22, S66), are very sensitive to basis set. It is well documented that inclusion of **diffuse basis functions** is crucial to accurately capture dispersion and induction components​[forum.psicode.org](https://forum.psicode.org/t/basis-set-recommendation-for-the-sapt-dft-method/2363#:~:text=It%20seems%20that%20my%20computation,TZVPD)​[forum.psicode.org](https://forum.psicode.org/t/basis-set-recommendation-for-the-sapt-dft-method/2363#:~:text=I%20know%20that%20for%20DFT%2C,diffuse%20functions%20are%20quite%20important). A conventional choice for high-accuracy SAPT is aug-cc-pVTZ or larger; however, these come at steep computational cost. Researchers have therefore explored truncated or optimized basis sets that balance cost and accuracy. One successful family is the “**calendar basis sets**” – for example, **jul-cc-pVDZ** and **jun-cc-pVDZ**, which systematically remove some diffuse functions from the aug-cc-pVXZ sets​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=In%20addition%20to%20these%20well,remove%20the%20diffuse%20functions%20with)​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=note%20that%20jun,order%20perturbation). _Jul-cc-pVXZ_ means no diffuse on hydrogens (keeping augments on heavy atoms), and _jun-cc-pVXZ_ goes further by also removing the highest angular-momentum diffuse functions on heavy atoms​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=note%20that%20jun,order%20perturbation)​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=match%20at%20L438%20jun%2C%20jul%2C,pVQZ%20calculations%20due%20to). This tweak was found to yield excellent error cancellation for SAPT. In fact, jun-cc-pVDZ has been highlighted as a remarkably robust compromise basis for SAPT0: it yields a **mean absolute error ~0.5 kcal/mol on the S66 set**, with maximum error ~1.6 kcal/mol​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=jun%2C%20jul%2C%20or%20aug,pVQZ%20calculations%20due%20to)​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=complexes%2C90%20the%20MAE%20for%20SAPT0%2Fjun,of%20the%20S66%20dimers%20are). This is more accurate than even some larger bases – for example, SAPT0 with jun-cc-pVDZ outperforms aug-cc-pVDZ (MAE ~0.67 kcal/mol) and even jun-cc-pVTZ (MAE ~0.8 kcal/mol) on S66​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=jun%2C%20jul%2C%20or%20aug,pVQZ%20calculations%20due%20to)​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=jun,pVTZ%200.81%203.34). The reason is that smaller bases _underestimate dispersion_, which fortuitously cancels the intrinsic tendency of second-order perturbation to overshoot dispersion energy​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=larger%20basis%20sets%20as%20compared,basis%20sets%20to%20delete%20diffuse)​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=the%20use%20of%20jun,remarkably%20robust%20compromise%20in%20small). In essence, **jun-cc-pVDZ hits a “Pauling point”** where basis incompleteness error and perturbation theory error balance out, yielding total interaction energies close to the basis-set limit​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=match%20at%20L453%20the%20use,remarkably%20robust%20compromise%20in%20small)​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=the%20use%20of%20jun,remarkably%20robust%20compromise%20in%20small).

For higher accuracy, moving to triple-zeta with diffuse is necessary. **Aug-cc-pVTZ** typically brings SAPT0 energies within ~0.5 kcal/mol of the CBS limit for small dimers, and even hydrogen-bond energies converge to better than 0.2–0.3 kcal/mol by aug-cc-pVQZ​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=reduced%20by%20minimal%20augmentation%2C%20e,5%20kcal%2Fmol%20but%20there). However, these larger aug-cc-pVXZ sets can be prohibitively expensive. Therefore, **recommended “medium” basis sets** for SAPT(DFT) often include things like **jun-cc-pVTZ** or **def2-TZVPPD** as alternatives​[forum.psicode.org](https://forum.psicode.org/t/basis-set-recommendation-for-the-sapt-dft-method/2363#:~:text=hokru%20%20November%2026%2C%202021%2C,9%3A05am%20%202). In a Psi4 developers’ discussion, def2-TZVPPD (a diffuse-augmented triple-zeta in the Ahlrichs basis family) was described as “a fine choice, better than aug-cc-pVDZ” for SAPT(DFT)​[forum.psicode.org](https://forum.psicode.org/t/basis-set-recommendation-for-the-sapt-dft-method/2363#:~:text=hokru%20%20November%2026%2C%202021%2C,9%3A05am%20%202). Likewise, trying **jun-cc-pVTZ** was suggested if computationally affordable​[forum.psicode.org](https://forum.psicode.org/t/basis-set-recommendation-for-the-sapt-dft-method/2363#:~:text=def2,D%20augmentation). Both approaches (removing diffuse on H and highest-$\ell$ on others, or using the def2 segmented basis with diffuse) aim to reduce basis size while retaining critical diffuse character for non-covalent interactions. In hydrogen-bonded systems, the electrostatic term also benefits from having polarization functions (d, f) on hydrogens – but in practice, diffuse functions on hydrogen often contribute little to binding energy while greatly expanding the basis. Thus, stripping diffuse on hydrogens (as jun/jul sets do) is usually safe​[forum.psicode.org](https://forum.psicode.org/t/basis-set-recommendation-for-the-sapt-dft-method/2363#:~:text=You%20can%20also%20see%20if,D%20augmentation).

**Basis Set Superposition Error (BSSE):** It’s worth noting that SAPT inherently avoids BSSE by using a dimer-centered basis (monomers are computed in the full dimer basis with the partner’s functions as ghosts)​[molpro.net](https://www.molpro.net/manual/doku.php?id=symmetry-adapted_intermolecular_perturbation_theory#:~:text=,2). So unlike supermolecular methods, one does not perform counterpoise corrections – but one must ensure the chosen basis is used consistently for the dimer’s integrals. Psi4 handles this automatically when you request SAPT. The **density-fitting auxiliary basis** is another consideration: Psi4 by default will choose an appropriate fitting basis (for Coulomb and exchange) for SAPT. In recent versions (since Psi4 1.6, May 2022), the default DF basis for electrostatics in SAPT0 was switched to the JK-fit set (e.g. aug-cc-pVDZ-JKFIT) which gives a better description​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=May%202022%20c,see)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=fitting%20changes%20%20,basis%20set%E2%80%99s%20RI%20auxiliary%20basis). This change improved consistency between different SAPT modules (the traditional SAPT0 vs the SAPT(DFT) module’s first-order terms)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=dispersion%20term%20does%20not%20change,basis%20set%E2%80%99s%20RI%20auxiliary%20basis). In practice, a user should ensure that if using a custom basis or an unusual element, an appropriate auxiliary (JKFIT/RI) basis is specified or available, otherwise **basis incompatibility errors** can arise (Psi4 may throw an error if it can’t find a matching auxiliary basis).

**Summary:** For SAPT(DFT) on typical organic dimers (C, H, N, O, halogens), a **triple-zeta with diffuse** on heavy atoms is recommended for reliable component energies. **Double-zeta with diffuse** (like aug-cc-pVDZ or def2-SVPD) can be used for scans or large sets, with understanding that dispersion will be somewhat over-bound (but errors often cancel between similar systems). The jun-cc-pVDZ basis stands out in literature as a cost-effective choice giving surprisingly good total energies for small dimers​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=jun%2C%20jul%2C%20or%20aug,pVQZ%20calculations%20due%20to)​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=complexes%2C90%20the%20MAE%20for%20SAPT0%2Fjun,of%20the%20S66%20dimers%20are), so it is often used in large benchmark studies (it was employed in constructing large SAPT datasets, as noted below in ML section). If ultimate accuracy is needed (e.g. within ~0.1 kcal/mol), aug-cc-pVTZ or even aug-cc-pVQZ per monomer should be used​[asc.ohio-state.edu](https://www.asc.ohio-state.edu/herbert.44/reprints/JCTC_18_2308.pdf#:~:text=reduced%20by%20minimal%20augmentation%2C%20e,5%20kcal%2Fmol%20but%20there), albeit at greatly increased cost. In workflows, one strategy is to **start with jun-DZ or aug-DZ** for initial survey, then refine a few key points with aug-TZ to verify convergence.

## Common Errors in SAPT Workflows and Automatic Recovery Strategies

Despite the sophistication of SAPT codes, users often encounter practical issues when running large batches of SAPT calculations. Here we catalog typical error types and how to handle them:

- **SCF Convergence Failures:** Since SAPT requires SCF calculations for each monomer (and sometimes the dimer for certain higher-order terms), a common failure mode is one of the monomer SCF calculations not converging. This can happen, for example, with a difficult electronic structure or an ill-conditioned basis (especially with diffuse functions). In Psi4, if a monomer SCF fails to converge, the SAPT code may abort or throw a Python exception (e.g., “Failed to converge” error). To recover automatically, one can employ several tactics:
    
    1. **Increase Iterations and Adjust SCF Algorithm:** By default, Psi4 uses an accelerated convergence (ADIIS/EDIIS) for RHF. In tough cases, turning off these accelerators can help. For instance, developers suggested setting `scf_initial_accelerator = none` to force a traditional SCF update​[forum.psicode.org](https://forum.psicode.org/t/sapt0-read-error/2626#:~:text=jmisiewicz%20%20October%2021%2C%202022%2C,1%3A33pm%20%202). Also, raising the maximum iterations (`MAXITER`) from the default (e.g., to 150 or 200) allows the SCF more cycles to converge​[forum.psicode.org](https://forum.psicode.org/t/sapt0-read-error/2626#:~:text=molecule%20). These changes can be set via the Psi4 Python API before calling energy. If using an automated script, one could catch the convergence failure and then retry with `psi4.set_options({"MAXITER": 200, "SCF_INITIAL_ACCELERATOR": "NONE"})`. Converging the monomers with ROHF-UHF tricks is generally **not** recommended – one user tried an ROHF reference to bypass RHF failure, but a Psi4 developer noted “if you can converge ROHF, you should be able to converge RHF” and that using an open-shell reference for a closed-shell system is not advisable for SAPT​[forum.psicode.org](https://forum.psicode.org/t/sapt0-read-error/2626#:~:text=jmisiewicz%20%20October%2021%2C%202022%2C,1%3A33pm%20%202)​[forum.psicode.org](https://forum.psicode.org/t/sapt0-read-error/2626#:~:text=loriab%20%20October%2024%2C%202022%2C,3%3A01am%20%204) (indeed, SAPT code may not handle the open-shell case correctly).
        
    2. **Better Initial Guess:** Using a more robust initial guess for the monomer orbitals can prevent SCF divergence. Psi4 provides the option of a **density-fitting guess** from a minimal basis. For example, setting `df_basis_guess = 6-31+G*` will first construct a guess density in the 6-31+G* basis (which is smaller and easier to converge) and then project it to the target basis​[forum.psicode.org](https://forum.psicode.org/t/sapt0-read-error/2626#:~:text=molecule%20). This was shown to salvage a difficult case: by adding `df_basis_guess 6-31+g*` and increasing MAXITER, a previously divergent SAPT0/aug-cc-pVDZ calculation finally converged (albeit taking ~24 hours for a complex dimer)​[forum.psicode.org](https://forum.psicode.org/t/sapt0-read-error/2626#:~:text=molecule%20)​[forum.psicode.org](https://forum.psicode.org/t/sapt0-read-error/2626#:~:text=Many%20thanks%21%20I%20will%20take,a%20try). Automating this, one could implement a fallback: if SCF fails with the direct guess, then set a simpler `df_basis_guess` and retry.
        
    3. **Level Shifting or Damping:** Although not specific to Psi4’s API in exposed form, general SCF techniques like adding a level shift to virtual orbitals or damping the first few iterations can help convergence. Psi4’s options (like `DIIS_START` to delay DIIS) can be tuned. An automation script might preemptively apply mild damping for systems known to be troublesome.
        
- **Memory and Disk Errors:** SAPT computations, especially SAPT(DFT) or higher-order SAPT, can be **memory intensive**. Large dimer bases and density-fitting intermediates may not fit in core memory, causing disk swapping or crashes. Users have reported cases where SAPT0/aug-cc-pVDZ on a ~150-atom system generated **>3 TB of scratch files**​[forum.psicode.org](https://forum.psicode.org/t/too-large-scratch-file/2607#:~:text=Dear%20all%2C)​[forum.psicode.org](https://forum.psicode.org/t/too-large-scratch-file/2607#:~:text=That%20does%20sound%20like%20a,Is%20the%20calc%20actually%20stopping). To manage this, one strategy is to **limit resource usage**:
    
    1. **Use Density-Fitting and Freeze Core:** Ensure all SCF calculations are using density fitting (`set scf_type df` in Psi4) so that 4-index integrals are avoided​[forum.psicode.org](https://forum.psicode.org/t/too-large-scratch-file/2607#:~:text=That%20does%20sound%20like%20a,Is%20the%20calc%20actually%20stopping). Also, freeze core orbitals (`freeze_core true`) so that perturbation steps (e.g., MP2 dispersion) do not include core electrons​[forum.psicode.org](https://forum.psicode.org/t/too-large-scratch-file/2607#:~:text=That%20does%20sound%20like%20a,Is%20the%20calc%20actually%20stopping). These reduce both memory and disk I/O. In the 150-atom example, a developer noted these should be turned on, along with using a smaller basis (e.g. jun-cc-pVDZ instead of aug-cc-pVDZ), to control scratch size​[forum.psicode.org](https://forum.psicode.org/t/too-large-scratch-file/2607#:~:text=That%20does%20sound%20like%20a,other%20than%20for%20disk%20full).
        
    2. **Sufficient Scratch Disk and Split Jobs:** If a single SAPT job is too large, an automation approach might split the task. For example, one could compute electrostatics + exchange with a moderate basis, and only compute the expensive dispersion with a reduced set or in pieces (though Psi4 doesn’t natively split SAPT components into separate jobs easily, one could in principle compute dispersion via an MP2 on monomers difference). In practice, the easier route is to ensure the machine has enough disk and set Psi4’s scratch directory to a location with space. An **automation script** can monitor the disk usage (Psi4 prints file sizes as it writes) and abort if it grows dangerously, then perhaps switch to a smaller basis or skip that case.
        
    3. **Memory Allocation Errors:** Psi4 will usually throw a Python exception if it cannot allocate needed memory. Catching this exception, one could programmatically reduce the basis or turn on more integral screening. The Psi4 option `memory` can be set at runtime; an automation could start with a high memory setting (to encourage in-core compute) but if an error “Matrix too large” or similar occurs, retry with a lower memory setting to force out-of-core algorithms.
        
- **Basis Set Compatibility Issues:** Another class of errors arises from **incompatible or missing basis set data**. For instance, using a basis that lacks functions for a certain atom, or failing to provide a JK-fitting basis for a method that needs one. In SAPT(DFT), one must use asymptotically corrected functionals; Psi4 requires the user to input a **GRAC shift** (the difference between true IP and Kohn-Sham HOMO) for each monomer​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=SAPT,it%20is%20recommended%20to%20enable)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=Regulated%20Asymptotic%20Correction%20scheme%20,scaling%20from%20the%20uncoupled%20value). If the GRAC shift is not provided, Psi4 will error or produce an incorrect long-range dispersion. Thus, an automation should include a step to obtain or estimate these shifts (e.g., using known values from NIST or a one-time ΔSCF calculation)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=For%20SAPT,Alternatively%2C%20one%20can%20estimate%20the)​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=program%20requires%20manual%20input%20of,LHF%29%20formulation%20and). For basis sets, Psi4’s recent versions handle auxiliary basis selection automatically in most cases. But if a user tries an unusual combination (say a custom orbital basis without specifying `DF_BASIS_SAPT`), an error could occur. The remedy is to specify an appropriate auxiliary (e.g., `set DF_BASIS_SAPT <basis>-RI` or `…JKFIT`). For example, when using def2-TZVPD in SAPT, one should also do `DF_BASIS_SAPT def2-TZVP` (since density fitting for that basis is defined) and perhaps `DF_BASIS_ELST def2-TZVPP-JKFIT` for best results​[forum.psicode.org](https://forum.psicode.org/t/basis-set-recommendation-for-the-sapt-dft-method/2363#:~:text=hokru%20%20November%2026%2C%202021%2C,9%3A05am%20%202). An **automation script** can maintain a mapping of common orbital bases to a good fitting basis and set them to avoid incompatibilities.
    
- **Fragment and Input Mistakes:** A simple but common error is not defining the dimer fragments correctly. If the input geometry is not split, Psi4 might either treat the whole thing as one molecule (then `energy('sapt0')` will complain there is only one fragment) or if a ghost atom specification is wrong, it could confuse the program. The automation should ensure the geometry is given in a format like Psi4’s `molecule { ... \n --\n ... }` or use Psi4’s `psi4.geometry()` with explicit fragmentation. Psi4 will raise an error if a third fragment with non-ghost atoms is present​[psicode.org](https://psicode.org/psi4manual/master/sapt.html#:~:text=SAPT%3A%20Symmetry,is%20not%20currently%20supported), as mentioned, so the script could verify only two real fragments are present.
    

**Automatic Recovery Implementation:** In practice, building a _robust_ SAPT automation means implementing a **retry logic**. For example:**

for geom in geometries:
    try:
       result = psi4.energy('sapt(dft)', molecule=geom, **options)
    except Exception as e:
       if "Failed to converge" in str(e):
           psi4.set_options({"SCF_INITIAL_ACCELERATOR": "NONE", "MAXITER": 200,
                             "DF_BASIS_GUESS": "6-31+G*"})
           result = psi4.energy('sapt(dft)', molecule=geom, **options)
       elif "MemoryError" in str(e) or "scratch" in str(e):
           reduce_basis_or_accuracy()
           result = psi4.energy('sapt0', molecule=geom, **options)
       else:
           log_error(e)
           continue
    process(result)

This pseudocode shows catching specific issues and adjusting. Indeed, the **best practices** distilled from user experiences include: use density-fitting, freeze core, avoid too aggressive extrapolations, and try smaller basis for initial guesses​[forum.psicode.org](https://forum.psicode.org/t/sapt0-read-error/2626#:~:text=molecule%20)​[forum.psicode.org](https://forum.psicode.org/t/too-large-scratch-file/2607#:~:text=That%20does%20sound%20like%20a,other%20than%20for%20disk%20full). With such measures, many SAPT failures can be turned into successes without manual intervention.

## Machine Learning Predictions of SAPT Interaction Energies (2022–2024)

In recent years there has been a surge of interest in using **machine learning (ML)** to predict intermolecular interaction energies – including the individual SAPT components – directly from molecular geometry or descriptors. The motivation is clear: high-level SAPT calculations are costly, but if one can train an ML model on a set of dimers (with inputs like coordinates or derived features) to predict $E_{\rm elst}$, $E_{\rm exch}$, $E_{\rm ind}$, $E_{\rm disp}$, etc., then one gains a fast surrogate model that retains physical interpretability (through the SAPT components)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=AP,44%20The)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=individual%20SAPT%20components%20of%20the,followed%20by%20induction%2C%20and%20then). Here we review developments from roughly 2022 onward:

**Large SAPT Datasets:** A prerequisite for ML is ample training data. Several large datasets have been published. Notably, in 2023 the **“Splinter” dataset** (Sherrill et al.) was released, containing about _1.7 million dimer configurations_ of protein–ligand fragment pairs, all with SAPT0 energy decompositions​[nature.com](https://www.nature.com/articles/s41597-023-02443-1#:~:text=With%20the%20aim%20of%20developing,were%20generated%20randomly%20from%20a)​[nature.com](https://www.nature.com/articles/s41597-023-02443-1#:~:text=protein,were%20generated%20randomly%20from%20a). Each entry includes the total interaction energy and the SAPT0 components (electrostatics, exchange, induction, dispersion) computed in two basis sets. The goal of Splinter was to provide a benchmark for training ML models on biologically relevant intermolecular interactions​[nature.com](https://www.nature.com/articles/s41597-023-02443-1#:~:text=reasonable%20accuracy%20with%20modest%20computational,polarization%2Finduction%2C%20and%20London%20dispersion%20effects1)​[nature.com](https://www.nature.com/articles/s41597-023-02443-1#:~:text=new%20systems%20are%20much%20less,relative%20energies). Similarly, an earlier dataset called **DES370K** (2019–2021) contains 370,000 dimers (generic small molecules) with energies at CCSD(T) CBS as well as SAPT0 for each​[researchgate.net](https://www.researchgate.net/figure/Partial-atomic-charges-in-1-2-ethanediol-Beside-each-atom-is-a-column-of-three-numbers_fig1_51986976#:~:text=Partial%20atomic%20charges%20in%201%2C2,Thus)​[nature.com](https://www.nature.com/articles/s41597-021-00833-x#:~:text=,This%20database%20features%20370%2C959). Another is **SAPT-10K** (2023) with about 10k high-quality SAPT data points for smaller dimers​[pubs.aip.org](https://pubs.aip.org/aip/jcp/article/160/18/184103/3290460/Ab-initio-dispersion-potentials-based-on-physics#:~:text=Ab%20initio%20dispersion%20potentials%20based,and%20their%20binding%20energy%20components). The existence of these datasets has enabled training of complex neural networks.

**ML Model Architectures:** The state-of-the-art models are usually graph-based neural networks that can ingest two molecular graphs (or a combined graph of the dimer) and output energy components. For example, in 2024, a “physics-aware” neural network called **AP-Net** was reported for protein–ligand interactions​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=1,be%20partitioned%20into%20atomic%20properties)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=2,pairwise%20additive). AP-Net is designed with inductive biases reflecting intermolecular physics: it has separate modules that predict atomic properties (like multipoles) and then pairwise interaction energies, enforcing that the total is a sum of pair contributions​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=2,pairwise%20additive)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=In%20reference%20to%20the%20second,an%20electrostatic%20force%20field%2C%20a). Crucially, AP-Net’s architecture enforces a decomposition into the standard SAPT components – essentially the network learns to predict $E_{\rm elst}$, $E_{\rm exch}$, $E_{\rm ind}$, $E_{\rm disp}$ in a way consistent with physical constraints​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=symmetry,2)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=AP,44%20The). When trained on the Splinter dataset (1.5 million training dimers, with aDZ basis SAPT0 data), the AP-Net model achieves impressive accuracy: a **mean absolute error of ~0.20 kcal/mol** on total SAPT0 energy, with >97% of validation dimers predicted within 1 kcal/mol​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=match%20at%20L256%20AP,44%20The)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=AP,44%20The). Even more striking, the _individual SAPT components_ are learned with MAEs smaller than that of the total energy​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=AP,44%20The)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=individual%20SAPT%20components%20of%20the,followed%20by%20induction%2C%20and%20then). This suggests the model captures the physical patterns of each component. For instance, it was observed that electrostatics and exchange are the hardest to predict (largest errors), whereas induction and especially dispersion were learned most accurately​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=match%20at%20L260%20individual%20SAPT,followed%20by%20induction%2C%20and%20then). This is perhaps intuitive: electrostatics and exchange depend sensitively on exact charge overlap at short range, which can vary non-linearly, whereas dispersion is a smoother long-range effect that might be easier for a neural network to fit.

Another noteworthy effort is by Chan et al., who in 2022 developed an ML model to predict **atomic multipole moments** up to quadrupoles, thereby reproducing the entire molecular electrostatic potential​[pubs.acs.org](https://pubs.acs.org/doi/10.1021/acs.jctc.1c01021#:~:text=Learning%20Atomic%20Multipoles%3A%20Prediction%20of,multipoles%20up%20to%20the%20quadrupole). While not directly predicting SAPT energies, such models can form components of a SAPT predictor (since once you have charges and dipoles, one can get an electrostatic energy, etc.). The general trend across 2022–2024 is that **equivariant graph neural networks** (which respect rotation symmetry) are being applied to learn intermolecular forces and energies. Some models (e.g., SchNet-based or PaiNN-based) have been trained on S66 and S66x8 (dimers at various separations) to predict _total_ interaction energies; these can achieve small errors but they do not provide decomposed components. The new frontier, as exemplified by AP-Net, is **multi-output networks** that yield the SAPT decomposition.

**Use of Benchmark Sets:** The S66 set itself (66 dimers with reference CCSD(T) energies) has often been a _testing ground_ rather than a training set for ML, due to its small size. For example, an ML model may be trained on thousands of other dimers and then tested on S66 to see if it generalizes. In one case, a 2019 study trained neural nets on hydrogen-bonded systems including amide–amide pairs (126 molecules including N-methylacetamide) with SAPT0 data, and could predict H-bond energies within ~0.5 kcal/mol​[pubs.aip.org](https://pubs.aip.org/aip/jcp/article/152/7/074103/1059677/Approaches-for-machine-learning-intermolecular#:~:text=Approaches%20for%20machine%20learning%20intermolecular,of%20common%20interest%20to)​[pubs.aip.org](https://pubs.aip.org/aip/jcp/article/152/7/074103/1059677/Approaches-for-machine-learning-intermolecular#:~:text=We%20train%20neural%20networks%20with,of%20common%20interest%20to). As data grew, focus shifted to larger sets like DES370K.

**Physical Insights and Limitations:** ML models like AP-Net are being designed to obey physical laws (for example, AP-Net enforces the correct $R^{-n}$ asymptotic decay for each component in the far dissociation limit)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=1,be%20partitioned%20into%20atomic%20properties)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=4,and%20smoothly%20decay%20to%20zero). This is crucial for reliability outside the training range. The 2024 AP-Net work also introduced a **SAPT-PDB-13K** test set – 13,216 dimers extracted from actual protein-ligand crystal structures, involving full drug-like molecules and amino acid residues​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=match%20at%20L276%20diverse%2C%20realistic,from%20crystallographic%20Protein%20Data%20Bank)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=diverse%2C%20realistic%20dataset%20of%20dimers%2C,from%20crystallographic%20Protein%20Data%20Bank). The ML model trained on smaller fragments (Splinter) was able to generalize well to these larger, more diverse dimers​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=dimer%20from%20the%20SAPT,3)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=The%20diversity%20of%20the%20SAPT,predicts%20the%20SAPT0%20interaction%20energy), with only slight degradation (interestingly, induction term predictions showed a bit more error relative to other terms in the PDB set​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=match%20at%20L294%20on%20the,4%20that%20the%20predicted)). This demonstrates the potential for **robust, general ML surrogates** for SAPT: one could foresee an ASE-compatible “ML-SAPT” calculator that, given two molecules, instantly predicts the SAPT breakdown with near-quantum accuracy, which would be invaluable for screening interactions in materials or biochemistry. Indeed, the AP-Net authors report that their model’s prediction errors are much smaller than the intrinsic errors of the SAPT0 method or basis truncation itself​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=individual%20SAPT%20components%20of%20the,followed%20by%20induction%2C%20and%20then)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=efforts%20to%20predict%20the%20SAPT,followed%20by%20induction%2C%20and%20then) – in other words, the ML is essentially as good as SAPT0 aug-DZ, so any remaining discrepancy is because SAPT0/aug-DZ differs from the true CCSD(T) CBS values.

In summary, **2022–2024 ML research has made major strides**: from initial studies on small datasets like S66 and a few hundred dimers, to massive datasets and specialized neural networks that deliver SAPT component energies with chemical accuracy. This opens possibilities to integrate ML models into workflows – for example, using an ML model to quickly estimate SAPT(DFT) energies of thousands of dimer orientations, then only calling the expensive Psi4 SAPT on a few critical points to validate or refine the ML model (active learning). Publications and preprints in this period (e.g., by H. Chen and S.D. Chao​[mdpi.com](https://www.mdpi.com/1420-3049/28/23/7900#:~:text=the%20four%20SAPT%20energy%20components,data%20are%20aligned%20along%20the)​[mdpi.com](https://www.mdpi.com/1420-3049/28/23/7900#:~:text=reference%20line%20indicates%20a%20greater,data%20are%20aligned%20along%20the), or by Patel, Parkhill, Sherrill and others for AP-Net​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=AP,44%20The)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=individual%20SAPT%20components%20of%20the,followed%20by%20induction%2C%20and%20then)) illustrate that predicting **SAPT from geometry is no longer science fiction** but an achievable task with modern machine learning.

## Distributed Multipole Analysis (DMA) vs Point-Charge Models for Electrostatics

Accurate modeling of the **electrostatic interaction** between molecules is essential, since electrostatics often dominates in hydrogen bonds and strongly polar complexes. Classical force fields usually represent electrostatics using **point charges** on atoms (monopole approximation). While simple, point charges cannot capture directionality of charge distribution (for example, a carbonyl group’s polarized double bond, or the $\pi$-electron cloud of benzene). **Distributed multipole analysis (DMA)** offers a more faithful representation by assigning higher-order multipoles (dipoles, quadrupoles, etc.) to each atom​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=The%20DMA%20method%20was%20devised,two%20molecules%20in%20van%20der)​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=centers%20correspond%20to%20the%20atoms,two%20molecules%20in%20van%20der). Prof. Anthony Stone’s DMA method (using Gaussian basis wavefunctions) generates atomic multipoles such that the sum of all atomic contributions exactly reproduces the molecular electron density’s multipole expansion​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=The%20DMA%20method%20was%20devised,two%20molecules%20in%20van%20der)​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=requirement,two%20molecules%20in%20van%20der). The key idea is that by taking into account up to, say, quadrupole moments on each atom, one can accurately reproduce the electrostatic potential of the molecule in space, not just at long range but even at intermolecular contact distances. In fact, the _radius of convergence_ of the multipole series around each atom is small enough that two molecules in van der Waals contact still see each other’s multipole expansion converging​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=multipole%20expansion%20was%20earlier%20proposed,in%20van%20der%20Waals%20contact)​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=requirement,two%20molecules%20in%20van%20der) (unlike a single-center expansion which would diverge at close range).

**Horton and “Part” Analysis:** The open-source library **HORTON** (Helpful Open-source Research Tool for N-fermion systems) provides functionality to compute distributed atomic multipoles via various **atoms-in-molecules (AIM) partitioning schemes**​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=HORTON%20supports%20several%20real,charge%2C%20atomic%20multipole%20expansion%2C%20etc)​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=wavefunction%20or%20cube%20file%2C%20several,charge%2C%20atomic%20multipole%20expansion%2C%20etc). In particular, HORTON has a module called **WPart** (wavefunction partition) and **CPart** (cube density partition) which can perform partitioning like Hirshfeld, Iterative Stockholder (ISA), etc., to obtain atomic charges and multipoles​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=Hirshfeld%20X%20X%20,X%20Pure%2Fharmonic%20multipoles%20X%20X). “HORTON-Part” likely refers to using HORTON’s partitioning tools to get distributed multipoles. For example, one can take a wavefunction file (from Psi4, Gaussian, ORCA, etc.) and run `horton-wpart.py` to produce atomic multipoles up to a specified order​[github.com](https://github.com/theochem/horton/blob/master/scripts/horton-wpart.py#:~:text=help%3D%27The%20maximum%20angular%20momentum%20to,consider%20in%20multipole%20expansions). HORTON supports **iterative stockholder (ISA) partitioning**​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=Hirshfeld%20X%20X%20,X%20Pure%2Fharmonic%20multipoles%20X%20X), which is a modern variant yielding well-behaved atomic densities (Verstraelen’s MBIS method is in this family). The output would be, for each atom, Q00 (monopole = charge), Q10...Q11 (dipole components), Q20... (quadrupole components), etc.​[researchgate.net](https://www.researchgate.net/figure/Partial-atomic-charges-in-1-2-ethanediol-Beside-each-atom-is-a-column-of-three-numbers_fig1_51986976#:~:text=Partial%20atomic%20charges%20in%201%2C2,Thus). These can be truncated at a chosen order – including just monopoles gives an atomic charge model, including dipoles yields a polarizable charge model (if dipoles allowed to rotate, as in some force fields), etc.

**Accuracy vs Point Charges:** Distributed multipole models are significantly more accurate than point charges for computing **interaction energies**. In essence, point charges are a zeroth-order truncation of the multipole expansion. They might be sufficient at very long range (where only the total charge matters to leading order), but at typical intermolecular distances (~3–5 Å) the dipole-dipole and higher terms contribute non-negligibly. For example, consider the electrostatic interaction of two water molecules: using just point charges (like TIP3P charges) yields an approximate interaction energy, but a DMA with charges and dipoles on each H and O can reproduce the _quantum electrostatic energy_ almost exactly (within a few percent)​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=requirement,in%20van%20der%20Waals%20contact)​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=The%20DMA%20series%20are%20derived,known%20as%20the%20overlap%20center). Another classic example is the benzene dimer: benzene has no net dipole, so a point-charge model would predict zero electrostatic attraction, but in reality benzene has a quadrupole moment; a distributed multipole model with quadrupoles can account for quadrupole–quadrupole attractions (which are important in stacking).

**Applications and Tools:** Many advanced force fields (AMOEBA, SIBFA) use multipoles rather than just charges, precisely to capture these effects. In the context of SAPT automation, one might use distributed multipoles in two ways: (1) **as a quicker estimator** for the electrostatic component $E_{\rm elst}$, and (2) as features for machine learning models (some ML models predict atomic multipoles as intermediate outputs​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=A%20schematic%20of%20the%20current,yields%20accurate%2C%20generalizable%20interaction%20energy)​[pubs.rsc.org](https://pubs.rsc.org/en/content/articlehtml/2024/sc/d4sc01029a#:~:text=NNs%2C%20which%20are%20respectively%20referred,centered%20multipole%20expansion.%20This%20physically)). If one had a large set of dimer geometries, instead of running a full SCF for each to get the exact electrostatics, one could compute atomic multipoles for each monomer once (from a high-quality density) and then compute electrostatic interaction energy for any relative orientation by summing Coulomb interactions of those multipoles. The formula involves tensor operations (charge-charge, charge-dipole, dipole-dipole terms, etc.), which are well-known​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=as%20linear%20combinations%20of%20atomic,known%20as%20the%20overlap%20center)​[en.wikipedia.org](https://en.wikipedia.org/wiki/Distributed_multipole_analysis#:~:text=If%20a%20basis%20of%20Gaussian,charge%2C%20dipole%20and%20quadrupole%20components). Tools like **GDMA** (Stone’s program) or HORTON can output the multipoles; then a custom script can calculate $E_{\rm elst} = \sum_{A\in mon1}\sum_{B\in mon2} E_{\rm multipole}(A,B)$ efficiently. When comparing to a simple point charge sum, the multipole expansion will generally be accurate much closer to the molecule. As an illustration, a point-charge model of a carbonyl group might put -0.5e on O and +0.5e on C; this yields a certain electric field. A multipole model might instead assign O a charge -0.3e, a dipole representing the lone pair orientation, and C a charge +0.3e and a dipole. The latter can reproduce the anisotropy: along the O=C axis vs perpendicular, the field is different – which a single point charge cannot do.

**Horton Integration:** Using HORTON in an automated workflow is feasible because HORTON is Python-based and can read Psi4 outputs. For instance, Psi4 can produce a Molden or FCHK file of the monomer densities; HORTON can load that (`IOData` in HORTON) and perform `compute_multipoles` via the `horton.part` API​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=,Orbital%20entanglement%20analysis)​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=%2A%205.1.3.%20horton,21). The **interface compatibility** is quite good: there’s even a simple template provided by HORTON for Psi4 outputs​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=,19)​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=,19). One could write a Python script that calls Psi4 for a monomer’s electron density, uses HORTON’s Python interface (no need to call the external script) to get atomic multipoles, and then uses those multipoles in any subsequent calculation. Notably, HORTON can output **Cartesian or spherical multipoles** up to any reasonable order​[theochem.github.io](https://theochem.github.io/horton/2.0.0/user_postproc_aim.html#:~:text=AIM%20properties%20Charges%20X%20X,tkatchenko2009%5D%20Spherical%20decomposition%20X). For most purposes, truncating at quadrupoles or octupoles per atom is sufficient.

**Comparing to Point-Charge Results:** Studies have shown that point-charge models often fail to predict the correct magnitude of electrostatic attraction in strongly polar complexes. For example, point charges might mis-evaluate the interaction of a chloride ion with water by several kcal/mol because they don’t account for polarization of the water – a multipole model inherently includes some polarization effect (since higher multipoles mimic how the electron density shifts). A recent review (Chen & Chao 2023) noted that classical Mulliken or RESP charges can vary widely and lack a consistent physical basis, whereas **methods like DMA or ISA (such as MBIS in HORTON)** provide more **chemically consistent charges and multipoles**​[researchgate.net](https://www.researchgate.net/figure/Partial-atomic-charges-in-1-2-ethanediol-Beside-each-atom-is-a-column-of-three-numbers_fig1_51986976#:~:text=Partial%20atomic%20charges%20in%201%2C2,Thus)​[researchgate.net](https://www.researchgate.net/figure/Partial-atomic-charges-in-1-2-ethanediol-Beside-each-atom-is-a-column-of-three-numbers_fig1_51986976#:~:text=,Thus). In an “atomic charges arboretum” study, DMA-based charges were among the more consistent and less basis-dependent ones compared to Mulliken or NBO charges​[researchgate.net](https://www.researchgate.net/publication/8179084_Charge_distribution_in_the_water_molecule-A_comparison_of_methods#:~:text=Charge%20distribution%20in%20the%20water,and%20poor%20charge%20values%2C)​[pubs.acs.org](https://pubs.acs.org/doi/10.1021/acs.jpca.7b08966#:~:text=,the%20nitrogen%20and%20oxygen%20series).

In conclusion, **distributed multipole analysis tools (e.g. HORTON’s wpart)** are invaluable for electrostatic modeling. They bridge the gap between full quantum Coulomb integrals and crude point charges. For a robust SAPT(DFT) automation module, one could integrate such a tool to, say, precompute monomer multipoles and use them as a fallback: if a SAPT calculation fails or is too slow, at least compute $E_{\rm elst}$ via multipoles as an approximation. This is much better than nothing, and for many orientations might be within a few percent of the true SAPT electrostatics. The **compatibility** is high since HORTON is open-source and scriptable, just like Psi4. Thus, a user-friendly SAPT workflow in Python could allow a toggle: _“fast mode: use distributed multipole electrostatics and ML-predicted dispersion; high-accuracy mode: perform full SAPT(DFT)”_. The availability of these tools and datasets in 2025 makes such multi-fidelity workflows a reality.
